新安装时应用通知转发默认关闭、应用白名单为空；已有配置保持原值。

仍在使用 bark.1（需一次重新安装）：
旧版 bark.1 使用的 debug 签名私钥未保存，现已无法找回。
虽然本版包名相同、versionCode 提升，仍不能直接覆盖 bark.1。
1. 在旧版“设置 → 导出配置”保存配置文件或复制配置文本到安全位置。
2. 确认配置已保存，再卸载旧版。
3. 安装本版 APK，同意隐私政策，导入此前配置。
4. 重新授权短信、通知、电话等所需权限，并开启首页转发服务。
5. 在设置里开启电话提醒并选择 Bark 通道。
导出配置包含转发通道、规则、模板、SIM 自定义号码等；不会迁移日志和失败短信队列。

二、Bark 和 empty message
通用 Webhook 保留原 content/message 与元数据，并追加 Bark 接受的 body 字段。
仅写 content 无法让 Bark 将它作为推送正文。
短信 body 使用自定义模板渲染结果；没有模板则使用原短信；模板渲染为空则回退到原短信。
电量、充电、通道测试、电话提醒使用非空文本 body。
在通道里选择“Webhook（支持 Bark）”，填入：
https://api.day.app/你的Bark设备密钥/
自建服务也可以使用相应的服务器地址与设备密钥。
电话提醒独立于短信关键词规则，直接发到所选通道或全部通道。

三、电话提醒
位置：设置 → 电话提醒。
“来电时推送”：默认关闭，开启后每次普通 SIM 来电响铃推送一次。
“未接／拒接后再提醒一次”：默认关闭。响铃后没有进入通话状态而结束时再推送。
已接听的普通来电不发送未接提醒；拨出电话不发送来电提醒。
重复响铃回调去重；同一号码下次来电仍会再次提醒。
Android 7.0 及以上按当前活动 SIM 分别监听，消息中包含 SIM 卡槽标识；更早版本监听系统默认电话状态。
不包含微信、WhatsApp 等网络电话，也不提供自动拨号、接听或录音功能。
Android 状态回调无法精确区分未接与主动拒接；通话等待、会议通话的复杂切换由系统决定。

权限：
- 电话状态 READ_PHONE_STATE：来电监听所必需。
- 通话记录 READ_CALL_LOG：可选，仅取得正在来电的号码，不查询历史通话记录。
- 未授权号码权限、系统隐藏号码或运营商不给号码时，仍提醒“未知号码”。
- 某些 Android 系统限制通话记录权限；可在系统设置尝试授权。
首页转发必须开启，并保留系统通知及后台运行权限。
电话接口由前台服务维护；新增受系统保护的 PHONE_STATE 广播入口作为备用，两者共用一个通话会话去重。
关闭首页转发或关闭电话提醒后，两个入口都不再推送。系统强行停止应用可能阻断广播，重新打开应用可恢复。
电话提醒的号码、时间、SIM 标识与设备型号会发送到您配置的目标。
日志页显示监听缺失原因、最近电话状态及各通道发送结果。电话提醒没有持久化离线重发队列；网络失败会记录日志。

四、永久签名备份与后续覆盖升级
单独提供 smsforwarder-bark-signing-backup.zip，里面有：
- signing/smsforwarder-bark.jks：此次签名私钥。
- bark-signing.properties：路径、别名、密钥库密码、私钥密码。
- SIGNING-README.txt：密码与使用说明。
别名：smsforwarder-bark。密码在备份包内，两处密码相同。
这不是 Bark 推送设备密钥；它用于给 Android APK 签名。
从 bark.2 起，以后使用同一份私钥、相同包名并提高 versionCode 的版本可覆盖升级并保留配置。
源码包不含私钥。请单独保留签名备份，不要重新生成替代密钥。

五、应用通知转发
位置：设置 → 应用通知转发。
1. 开启“转发选定应用的通知”。
2. 点击“授权通知访问”，在系统列表中开启“短信转发助手 Bark（应用通知）”。
3. 点击“选择应用”，勾选微信、邮件、聊天等希望转发通知的应用。
4. 选择推送通道，例如原有的 Webhook / Bark 通道。
5. 在首页开启转发服务，再让选定应用收到一条新消息。
首页关闭转发或点击前台通知的停止按钮时，应用通知转发也停止。
应用在通知栏显示的名称、标题、正文、时间与设备型号会作为非空 Bark body 转发。

避免重复：
- “跳过短信／电话应用”默认开启。识别当前默认短信/拨号应用和常见系统短信、电话包。
- 默认将短信和 SIM 来电交给原有功能，应用通知不再从这些软件重复推送。
- 排除针对整个应用，因此短信软件中的 RCS 等消息也默认跳过；需要时可关闭过滤并调整原有短信规则。
- 本应用自身通知始终排除，避免转发助手通知循环。
- 分组汇总通知始终跳过，优先转发单条消息；常驻、音乐播放、下载进度和前台服务提示默认跳过。
- 相同通知标识和内容不会因重复回调再推送；同一通知正文更新后可继续推送。
- 普通通知同一内容在 3 秒内的重复重建会合并；MessagingStyle 新消息有不同时间标识时仍会分别推送。
- 消息式通知取最近一条消息，不重复发送其历史列表。
- 仅保存最多 300 条通知标识和正文的 SHA-256 哈希及处理时间，最长 24 小时，不保存通知正文。
- 删除通知后可用同一标识再次推送；监听重连/进程重启后可恢复哈希去重。

哪些情况下仍可能重复：
关闭短信／电话过滤并选中这些应用；其它软件再次展示同一条短信/来电；应用把相同内容重发成不同的新通知。
原有“未接／拒接后再提醒一次”打开时，响铃一次、未接结束再一次，是独立的两种事件。
不同通道配置到同一个 Bark 地址，也可能产生多次推送；可为电话和应用通知各指定一个通道。

权限与内容限制：
- 必须单独授予系统“通知访问”；已有的“显示通知”权限不能替代它。
- 若系统显示“受限设置”，进入系统设置 → 应用 → 本应用详情 → 更多菜单，按系统提示允许受限设置后再授权。
- 只处理选定应用在系统通知栏提供的文字。应用未发布通知、正文被隐藏或自定义通知不提供文字时，无法读取完整消息。
- Android 15 起，对不受信任通知监听应用可能脱敏验证码等敏感内容；原有短信广播转发仍走独立流程。
- 图片/附件不下载；消息式通知可显示“[媒体消息]”。过长正文按 UTF-8 字节安全截断，并标明截断。
- 不读取应用内部聊天记录，不请求无障碍权限，不主动遍历旧通知。
- 应用列表展示可打开的应用及已观察到的通知来源；未列出的来源收到通知后可刷新列表。
- 应用通知没有持久化离线重发队列，网络失败会在日志中显示发送失败。

将签名备份解压到源码项目 smsforwarder-bark 根目录，保留 signing/ 路径。

./gradlew :app:testDebugUnitTest :app:assembleBark -PVERSION_NAME=2.9.8 -PVERSION_CODE=4

八、本次电话监听修复与手机验证
本版针对“短信推送成功，但来电没有日志”的反馈修复电话监听启动和兼容性，并加入诊断。
截图不能独立证明具体设备的故障原因；仍需安装后实测一次新来电。
1. Android 12/API 31 及以上使用 TelephonyCallback.CallStateListener，并保留强引用、主线程执行器及按 SIM 注册。
   更早版本继续使用 PhoneStateListener。注册失败时不会错误标记接口已开启。
2. 新增 PHONE_STATE 系统广播备用入口，不从后台广播强行启动前台服务。
   新接口、旧接口和广播都交给同一会话路由，普通重复响铃及结束不会重复发送。
   系统可能先送不含号码的广播，再送含号码的广播，也可能顺序相反；未知号码来电延后 500ms 合并信息。
   电话状态权限缺失会明确显示；来电号码权限仍是可选，不影响推送未知号码。
3. 打开应用及设置/授权返回时，依据已保存的全局转发开关恢复服务。
   “重新检查监听”会真正注销再注册电话回调，并记录检查结果。
4. 设置页显示“最近监听状态”“最近电话事件”，新增“发送测试提醒”。
   通道测试只验证所选电话推送通道，不代表真实电话监听已收到事件。
5. 本应用及电话/短信应用通知过滤仍按 bark.3 的配置工作；应用通知过滤不拦截原生 SIM 来电提醒。

请按以下步骤验证：
- 覆盖安装 bark.4，打开应用，确认首页转发和“来电时推送”均已开启。
- 设置 → 电话提醒：确认电话状态权限已授权，选中 Bark 通道，点击“重新检查监听”。
- 最近监听状态应显示“电话提醒监听已开启”；否则按所显示的权限或通道缺失原因处理。
- 点击“发送测试提醒”。Bark 收到测试可证明通道可发送。
- 用另一部手机拨入一个新的普通 SIM 来电，响铃时检查 Bark 和日志。
- 日志应出现“电话状态：…响铃（新电话接口／电话接口／系统广播）”，随后“电话提醒 → Bark：成功”。
- 测试有推送但没有响铃日志：提供“电话提醒”设置卡和最新日志，以排查手机权限及系统对电话事件的限制。
- 有响铃日志但显示发送失败：检查日志中的通道结果及当时网络。

边界：不读取历史通话记录补发；只有普通 SIM 来电，不包含微信等网络电话。
双卡同时通话且广播没有 SIM 标识时，不把含糊的全局状态强行套到两张卡，优先使用每张卡的系统接口。
接口/广播的会话只保存在进程内，设备重启或完整进程重启后的在途通话去重由新事件重建。
真实三星手机的权限、后台运行和 iPhone Bark 到达仍需手机实测，本次没有模拟或声称完成这些设备验证。
